This project migrates financial transaction data from a COBOL mainframe system (IBM z/OS) to a modern relational database target system.

Source files are fixed-width flat files generated by COBOL batch programs. Each file has a header record (RECORD-TYPE = HD), multiple detail records (RECORD-TYPE = DT), and a trailer record (RECORD-TYPE = TRL). Files are received daily in batch.

The primary source datasets are: customer master file (CUST.MASTER), daily transaction file (TXN.DAILY), and account balance file (ACCT.BAL). Each is a separate fixed-width file with its own COBOL copybook definition.

The target system is a SQL Server relational database with normalized tables: CUSTOMERS, ACCOUNTS, TRANSACTIONS, and BRANCH_REFERENCE. Field names in the target follow PascalCase conventions (e.g. CustomerId, AccountNumber).

Key transformation rules: all date fields must be converted from YYYYMMDD to YYYY-MM-DD; all monetary amounts stored as PIC 9(9)V99 COMP-3 must be divided by 100; all text fields from fixed-width source must have trailing spaces trimmed; ACCOUNT_NUMBER must be prefixed with ACC-.

Reconciliation is performed by comparing TOTAL_RECORDS count and CONTROL_AMOUNT sum in the trailer record against the actual records processed. Any mismatch is a critical failure.

The branch reference table (BRANCH_REF) is a static lookup that must be loaded separately before transaction processing begins.

The migration runs quarterly with a full historical load followed by daily delta loads. The daily delta identifies changed records using the EFFECTIVE_DATE field.
